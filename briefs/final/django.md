# Corrected Django models (v2)

Output: `{{COUNCIL_DIR}}/output/plan/django/v2/` (one Python module per app), `{{COUNCIL_DIR}}/output/plan/django/v2/tests/` (pytest cases, as Python), and `{{COUNCIL_DIR}}/output/plan/django/v2/README.md`. Also write `{{COUNCIL_DIR}}/output/plan/final/drafts/django.md` describing what you produced and any residual issues.

Round 1's model drafts are the input to correct, not the files to extend in place. Read `django/` and `review2/data-backend.md` to learn what went wrong. Write the corrected MVP models from scratch, following the revised `decisions.md` and `CONVENTIONS.md`, so the app repo can start from models that match the plan.

1. Apps and models covering the MVP: tenants, locations (with an IANA time zone), memberships and roles with location scope (including the ADR's all-locations representation), staff and location assignments, programs, rewards, card design, customers (tenant-wide) with protected fields, passes, the append-only earn/redeem ledger with idempotency keys, balances that cannot change except through that ledger, and settings. Money fields, integer balances, ids, timestamps, names, and tenant foreign keys must follow the ADRs exactly. Every tenant-owned model uses the shared tenant manager.
2. Constraints the database enforces: unique idempotency key per tenant, non-negative balance, and any `RunSQL` the ORM cannot express. State `on_delete` for every foreign key.
3. Tests in `tests/` as pytest functions that fail when an expectation fails. At minimum: a user of tenant A cannot read, create, update or delete tenant B rows through the managers and the API; a location manager cannot act on another location; a stamper cannot change program rules; the same idempotency key cannot apply two ledger events; a redeem that would make the balance negative is rejected; a balance cannot be saved except by the ledger service the ADRs define; a customer cannot be linked across tenants through a foreign key.
4. `README.md`: what each app's models do, which ADRs they implement, how to read the tests, and any place where you had to interpret or deviate from an ADR (each one also listed as a residual issue in the `F-final-django-<n>` format, in `{{COUNCIL_DIR}}/output/plan/final/drafts/django.md`).
