## Findings

### F-backend-1: tenant message-cap and limiter-trip alerts are not wired
- Severity: minor
- Location: supabase/functions/_shared/rate_limit_quotas.ts:36 (MESSAGE_CAP_ALERT_RATIO defined, never referenced); COUNCIL.md "Gate findings" 1 and "Launch gate" (alerts item)
- Problem: the 80 % alert ratio constant and `rate_limit_trips` per-day/per-tenant refusal records exist, but nothing reads them; a monitor on the day's code-email count and on limiter trips is a launch-gate item with no code. Exposure at launch is reputation (a code-email flood stops at the 2,000/day tenant cap), not spend, and the team explicitly documented it as gate finding 1.
- Evidence: `grep -rn "MESSAGE_CAP_ALERT_RATIO" supabase/functions/` → only the definition (rate_limit_quotas.ts:36). COUNCIL.md:178-183 "Message-cost and limiter alerts are not wired … No code was changed at the gate."
- Fix: add a small ops-check script (e.g. `scripts/ops/limiter-alerts.sql`) that queries `rate_limit_trips` for today's refusals by tenant/rule and compares `pgmq`-free code-email counts to `messages.tenant` capacity, wired to the monitor/runbook, or delete the dead constant until the monitor exists.
- Plan item: ADR-47 (rate-limiting design includes failure mode/alerting); threat model "Message-cost abuse" (threat 3) and "Exhausting the limiter" (threat 8) findings 1.

### F-backend-2: local test-hook guards cannot tell a CLI-run self-hosted stack from a laptop
- Severity: minor
- Location: supabase/functions/_shared/local_stack.ts:4-11 (isLocalStack), 9.A-T6 note (COUNCIL.md open risk 15)
- Problem: a self-hosted stack started with the Supabase CLI has `SUPABASE_URL=http://kong:8000`, which `isLocalStack` treats as local, so the local-only test hooks (`MESSAGING_FAKE_ROUTING`, `MESSAGING_FAKE_CHANNELS`, `TURNSTILE_SITEVERIFY_URL`, `NOTIFY_BACKOFF_SCALE`) would be honored there if anyone set them. The only defense is the production secrets checklist (never set them in a hosted project). No current exposure on a correctly configured stack (email off/SMTP absent would make sends no-op), but the edge is real and was left "for the chair" by the team.
- Evidence: local_stack.ts:4-11 regex includes `kong`; COUNCIL.md open risk 15 "isLocalStack on a CLI-run self-hosted stack … left for the chair as it changes when test hooks apply".
- Fix (when a ruling approves): tie the fake-hook guards to `FUNCTIONS_PUBLIC_URL` being unset (a CLI-run production stack must set it, per 9.A-T6/runbooks), e.g. `isLocalStack && !env("FUNCTIONS_PUBLIC_URL")`, and add a boot refusal to `assertFakeRoutingAllowed` when `FUNCTIONS_PUBLIC_URL` is set.
- Plan item: ADR-33/ADR-35 (test hooks only on local); threat model "Secret leakage".
