## Biggest changes

1. **The GlowDesk evidence pipeline is now the build's spine (ADR-57).** Phase 0 creates `plan/evidence/`, `phase-0-progress.md`, `scripts/phase0-check.sh` (logs under `/tmp`, never in the repo), and `playwright.evidence.config.ts`. Every task writes its progress row in its own commit; every epic closes with `REVIEW.md` + numbered artifacts; every phase closes with a gate pack. All user-facing journeys are Playwright-tested in `en` **and** `ar`, with evidence screenshots in four variants (en-light, en-dark, ar-light, ar-dark) plus phone viewport. The rhythm is written into feature-delivery, react-frontend, CONVENTIONS §9/§11, and every phase of IMPLEMENTATION_PLAN.md. None of GlowDesk's Supabase/pgTAP/Deno/Edge-Function stack was adopted; Django, pytest, and Celery stay.
2. **Ledger and webhook phase sequencing fixed.** The complete `ledger_entries` schema (columns, idempotency unique, balance-events check, append-only trigger via `RunSQL`) is created in Phase 2 because enrollment writes `enroll` entries; Phase 3 adds `Balance` and the services. `webhook_subscriptions`/`webhook_deliveries` are created empty in Phase 3 so the fanout is a legal no-op; Phase 5 activates UI, credentials, and delivery. A migration-order test proves the Phase 2 enrollment transaction runs before Phase 3 code.
3. **Fourteen new ADRs (ADR-45..58)** cover the operational decisions the first audit missed: backup/DR, search, feature flags, environments, transactional email, queue routing, pass image validation, customer deduplication, migration policy, unified PII handling, monitoring/SLOs, cache policy, the evidence pipeline, and the round-2 scope rulings. Eight existing ADRs (1, 4, 9, 11, 22, 24, 34, 42) are amended in place, each marked `Revised in round 2:` with the finding ids. No ADR was renumbered; none was reversed.
4. **The tenant-isolation fence is real now.** The vacuous "import grep" is replaced by an attribute-access AST checker (`scripts/check_cross_tenant.py`) with a narrow allowlist (platform.py, outbox task files, migrations, reconciliation), every use audited; outbox Celery tasks get a legal, fenced, by-primary-key accessor; composite same-tenant FKs use `ForeignKey(..., db_constraint=False)` + migration `RunSQL` (the nonexistent `models.ForeignKeyConstraint` is gone and listed as a pitfall); the abstract tenant base declares no pk — each concrete model declares UUID (public) or `BigAutoField` (internal/join), enforced by a model-enumeration test.
5. **MVP backlog gaps scheduled:** owner/manager location CRUD (`/settings/locations`, Phase 1 Epic 1.3) and customer privacy deletion (service + audit + final pass void + confirm dialog, Phase 3 Epic 3.4).

## Deliberately left open

- **`django/*.py` draft code was not rewritten.** ADR-44 demotes these files to illustrative drafts that Phase 0 rewrites from the django-data skill; the round-2 fixes therefore landed in the binding layer (ADRs, CONVENTIONS, skills, plan). Each draft now carries a module-docstring status note naming its known deviations so nothing copies them by accident. Rewriting them now would create a second source of truth ahead of Phase 0.
- **Round-1 member reports were not otherwise edited.** Reviewer rules prohibit rewriting them; the only changes are the F-REQ-1 corrections in requirements.md (explicitly ordered by the adjudication) and the SUPERSEDED/ILLUSTRATIVE headers on backend.md and data-model.md (explicitly ordered for those two files). frontend.md and review.md are untouched.
- **Column-level encryption for customer PII** remains an open infrastructure decision inside ADR-54; the plan deliberately does not claim Postgres TDE exists or is configured.
- **Audit retention default** (ADR-42) ships as a configurable value pending counsel approval; the seven-year GCC figure is a default, not a legal assertion.
- **Monitoring thresholds** (ADR-55) are tunable config, not fixed truths; initial values are set in Phase 0 and revised from real traffic.
- **Transactional email provider** (ADR-49) is chosen and documented in Phase 1 behind the abstraction.
- **Deployment strategy** (ADR-48) is rolling-with-expand/contract by default; blue-green only where ops demonstrates a need.
